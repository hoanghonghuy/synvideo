# TASK-029 — Durable generated-image acquisition + MediaAsset ingestion

## Problem / Goal
Creators can now configure and resolve owner-scoped image providers, but SynVideo still lacks a durable production path from “generate image for this scene” to a persisted MediaAsset that can survive retries, worker crashes and provider/storage failures. Implement that missing acquisition/orchestration layer without introducing provider-specific data into durable domain state.

## Frozen contract
`docs/contracts/GENERATED_IMAGE_ACQUISITION_V1.md`

## Scope
- durable per-scene generated-image request/job using the existing durable job framework;
- owner/project/scene validation and owner-scoped image provider/model resolution;
- generated bytes/stream ingestion into existing object storage + MediaAsset persistence;
- safe generated provenance;
- optional/explicit scene primary-visual assignment using existing scene media binding;
- idempotent API retries and duplicate worker delivery;
- cancellation/timeouts and safe provider/storage error mapping;
- integration/regression coverage for generation→ingestion→assignment recovery boundaries.

## Non-scope
- video generation;
- TTS/narration/audio timing;
- stock media search;
- captions/music;
- editor/composition/render/publish;
- provider settings redesign;
- Media Library redesign.

## Required behavior
- unknown/disabled provider or model fails before generation;
- creator cannot generate/assign for a scene outside owner/project scope;
- successful provider output is copied into SynVideo-managed storage and represented by a durable MediaAsset before job success;
- no provider URL, credential, ciphertext, base URL, external model identity or raw upstream response is persisted in durable/public resources;
- retries/redelivery do not duplicate logical jobs, MediaAssets or scene assignments;
- if a result has already been durably ingested, recovery must not pay for unnecessary regeneration;
- storage/assignment failure after generation remains recoverable and truthfully visible;
- successful assignment uses existing scene-media invariants/history rather than bypassing them.

## Implementation notes
Reuse existing durable job abstractions, MediaAsset/storage ports, scene media binding and TASK-028 provider runtime. Keep provider adapter types/config outside durable job/domain payloads. Treat generation, durable ingestion and scene assignment as distinct recovery boundaries; choose a transaction/idempotency strategy that prevents duplicate paid work and duplicate durable assets without coupling domain code to one vendor.
