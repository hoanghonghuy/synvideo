# Generative Media Architecture Research — 2026-09

Status: PM/TL research note for post-WAVE-F1-H planning.

## Why this note exists
SynVideo has accepted provider-neutral capability IDs for text, image generation, video generation, TTS, transcription and music, plus durable jobs and S3-compatible Media Assets. The next media/audio work must reuse those foundations without pretending that image, video and speech providers share the same execution lifecycle.

## Accepted repository facts
- `providers.Capability` already includes `image_generation`, `video_generation`, `tts`, `transcription` and `music`.
- Media Asset already owns durable project-scoped binary identity and S3-compatible ingestion/storage.
- Scene Plan already stores scene-level visual instructions, planned source type and expected duration.
- Scene Media Binding owns history-safe primary visual selection for an approved Scene Plan version.
- Generic durable jobs own retries/leases but do not by themselves persist an external provider operation ID between handler attempts.
- Current owner BYOK runtime is intentionally text-provider specific and must not be silently stretched into arbitrary media-provider semantics without a separate contract.

## External provider lifecycle findings
Current mainstream provider APIs are materially different:
- image generation can complete synchronously/stream output in one request;
- video generation commonly returns a provider operation/job ID and requires later polling before bytes are downloadable;
- TTS can be synchronous streaming or an asynchronous generation lifecycle depending on provider/model.

Examples reviewed during planning:
- OpenAI Video API creates a queued video job and later exposes metadata/content retrieval;
- Google Vertex AI Veo uses a long-running video operation that is polled to completion;
- OpenAI speech can stream generated audio directly;
- ElevenLabs offers both direct TTS conversion and a separate asynchronous speech-generation flow.

## Architecture decisions for upcoming tasks
### 1. Do not define one universal `Generate() -> []byte` interface
Image, video and speech keep capability-specific ports. Common safe metadata may be shared, but asynchronous provider-operation semantics must remain explicit.

### 2. Durable provider operation identity is mandatory for async paid generation
For video-generation orchestration, the application must persist the opaque provider operation ID after the first successful submit and before relying on repeated polling. Worker crash/reclaim must continue polling the existing provider operation instead of blindly submitting and billing a second generation.

This persistence belongs to the feature orchestration layer, not the generic jobs table and not the provider adapter.

### 3. Provider output is never the durable product asset identity
Provider URLs, base64 payloads or remote operation IDs are transient transport details. Successful generated bytes are ingested into accepted `MediaAsset` storage and receive SynVideo-owned asset IDs/object keys before they can become current scene media.

### 4. Scene generation must snapshot accepted creative intent
Per-scene media generation later uses an approved Scene Plan version + exact scene key/visual instruction/aspect/duration intent as durable request input. A queued request must not silently switch to a newer Scene Plan at execution time.

### 5. Replacement/history remains separate from generation
A generated asset may succeed without automatically destroying an existing creator choice. Asset creation and Scene Media Binding replacement are distinct durable operations. Automatic binding is permitted only when the explicit request contract says so and remains idempotent.

### 6. Credentials stay out of durable jobs
Media provider credentials are resolved at execution from a secure runtime/configuration boundary, never serialized into job payload/result. Future media BYOK must reuse the accepted encryption/security principles but gets its own capability contract rather than leaking through text-specific types.

### 7. Stock media is not equivalent to generated media
Stock search/acquisition needs source URL/provider item/license/attribution provenance. It should get its own adapter contract instead of being forced into image/video generation interfaces.

### 8. Audio generation must plan for chunking and timing
Approved scene narration may exceed individual TTS provider text limits. Provider adapters should expose their real safe limits; later orchestration owns deterministic chunking/stitching/timing rather than silently truncating narration.

## Planning consequence
The post-H roadmap is sequenced as:
1. finish Script end-to-end and Scene Media Binding;
2. Scene Plan durable generation/API + workspace;
3. expose Media Asset storage and Scene Media Binding as creator-facing API/workspace;
4. freeze provider-neutral image/video ports;
5. implement a first live image/video adapter without runtime/job coupling;
6. freeze TTS + first speech adapter;
7. only then create paid per-scene visual/audio orchestration with durable external-operation state;
8. stock acquisition, captions/music, Scene Editor, render/export and publishing follow those stable media primitives.

This sequencing keeps the Scene Editor from becoming the place where unfinished storage/provider/job semantics are invented ad hoc.
